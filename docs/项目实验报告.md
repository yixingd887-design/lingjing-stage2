# 灵境后端 AI 第二阶段项目实验报告

## 一、项目背景与目标

### 1.1 项目背景

随着计算机视觉技术的发展，图像智能分析已经广泛应用于目标检测、场景理解和智能信息提取等任务。不同视觉技术在分析图片时具有不同的特点：传统目标检测模型能够识别图片中的特定物体并定位其位置，而视觉大模型能够结合图像内容生成自然语言描述，帮助用户理解图片所表达的场景信息。

为了了解不同视觉分析方案的特点，本项目以公交车场景图片为测试对象，分别采用 YOLO 目标检测模型和视觉大模型进行分析，并对两种方案的输出结果、响应耗时及适用场景进行比较。

### 1.2 项目目标

本项目主要完成以下目标：

1. 实现基于 YOLO 的图片目标检测，识别图片中的公交车、行人等目标，并输出检测类别、置信度和目标位置。
2. 接入视觉大模型 API，对同一张图片进行场景分析，获取自然语言形式的分析结果。
3. 记录两种方案的实验结果和运行耗时，分析其在目标定位、场景描述和响应效率方面的差异。
4. 总结两种视觉分析方案的优势、局限及适用场景，为后续选择合适的视觉智能技术提供参考。

### 1.3 项目主要成果

目前，项目已实现 YOLO 目标检测与视觉大模型图片分析两项功能，并使用同一张公交车图片完成了初步测试。程序能够输出目标检测结果、生成中文场景描述，并记录相关运行耗时。在此基础上，项目进一步整理实验记录和对比分析，为后续完善项目文档及演示材料提供依据。

## 二、技术方案与原理

### 2.1 系统总体方案

本项目采用两种视觉分析方案，对同一张公交车场景图片进行处理，并比较两种方案的输出结果。

第一种方案采用 YOLO 目标检测模型，对图片中的目标进行识别和定位，输出目标类别、置信度及边界框等信息。第二种方案通过视觉大模型 API 传入图片，获取图片内容的自然语言描述。

系统通过统一的测试图片和实验记录，对两种方案的功能特点、响应耗时和适用场景进行分析。

### 2.2 YOLO 目标检测原理

YOLO 是一种目标检测方法，能够在图像中识别目标类别，并预测目标在图像中的位置。

在本项目中，程序调用 YOLO 模型处理公交车场景图片，并将检测结果以可视化形式展示。检测结果包括目标类别、置信度和目标边界框。

其中，置信度用于表示模型对检测结果的确信程度，但不应简单理解为目标识别正确的绝对概率。目标检测结果可以帮助使用者快速了解图片中有哪些目标，以及这些目标大致位于什么位置。

### 2.3 视觉大模型分析原理

视觉大模型能够接收图像等多模态输入，并结合图像内容生成自然语言回答。本项目通过 API 将测试图片发送给视觉大模型，同时提供图片分析任务的文字提示，要求模型描述图片中的物体、环境和主要信息。

与主要输出目标类别和位置的目标检测模型不同，视觉大模型能够生成较为连贯的场景描述，便于使用者以自然语言理解图片内容。

但视觉大模型生成的描述也可能包含不准确的信息或未经图像充分支持的推断，因此仍需要结合原图核对，不能将所有描述都视为已经验证的事实。

### 2.4 两种方案的运行流程

**方案一：YOLO 目标检测**

1. 读取测试图片。
2. 加载 YOLO 目标检测模型。
3. 执行目标检测，获取类别、置信度和位置等信息。
4. 将检测结果绘制到图片上，并保存可视化结果。

**方案二：视觉大模型分析**

1. 读取测试图片。
2. 将图片编码为 Base64 格式。
3. 通过配置好的 API 客户端发送图片和文字提示。
4. 获取模型返回的自然语言分析结果。
5. 记录本次 API 调用的响应耗时，并展示分析文本。

## 三、实验环境与方法

### 3.1 实验环境

本项目使用 Python 开发，采用 PyTorch 及相关视觉处理工具完成目标检测功能，并通过 API 调用视觉大模型进行图片分析。

实验环境包括以下内容：

- 操作系统：Windows
- Python 版本：3.11.9
- 深度学习框架：PyTorch
- 目标检测工具：Ultralytics YOLO
- 图像分析方式：视觉大模型 API
- 硬件环境：NVIDIA GeForce RTX 5060 Laptop GPU

### 3.2 测试数据

本次实验选用项目目录中的 `images/bus.jpg` 作为测试图片。该图片包含公交车和行人等目标，适合用于观察目标检测模型的识别与定位能力，以及视觉大模型对场景内容的描述能力。

两种方案使用同一张图片进行测试，以减少测试对象不同带来的影响。

### 3.3 实验方法

本次实验分别运行 YOLO 目标检测程序和视觉大模型图片分析程序，并记录两种方案的输出结果。

对于 YOLO 方案，主要记录检测到的目标类别、目标数量、置信度、可视化结果及模型推理耗时。

对于视觉大模型方案，主要记录模型返回的场景描述、API 调用响应耗时，以及描述内容是否与原图一致。

实验过程中，对模型生成的内容进行人工核对，并注意区分模型输出、实测数据和人工分析结论。

### 4.1 YOLO 目标检测结果

使用 `images/bus.jpg` 进行目标检测，程序成功识别出公交车和行人，并生成可视化检测结果图片 `results_bus.jpg`。

从本次结果来看，YOLO 能够输出明确的目标类别、位置及置信度，适合需要识别目标并定位目标位置的任务。需要注意的是，上述数据仅代表当前测试图片的一次实验结果，不能直接推广为模型在所有场景中的普遍性能。

### 4.2 视觉大模型分析结果

将同一张公交车场景图片发送给视觉大模型 API 后，程序成功获得中文场景描述。返回内容涉及公交车、行人、建筑和街道环境等信息。

本次测试记录如下：

| 指标 | 实验结果 |
|---|---|
| 测试图片 | `images/bus.jpg` |
| 分析结果 | 成功返回中文场景描述 |
| API 响应耗时 | 17.11 秒 |
| 结果形式 | 自然语言文本 |

视觉大模型能够以较为连贯的自然语言描述图片内容，便于使用者理解整体场景。但其描述可能包含不准确的信息或未经充分验证的推断，因此需要结合原图进行核对。

### 4.3 实验结果对比

| 对比维度 | YOLO 目标检测 | 视觉大模型分析 |
|---|---|---|
| 主要输出 | 目标类别、置信度、边界框 | 自然语言场景描述 |
| 目标定位 | 能输出目标位置 | 本项目当前未实现结构化目标定位输出 |
| 场景理解 | 主要围绕已检测目标 | 能生成整体场景描述 |
| 本次耗时记录 | 模型推理约 6.9 毫秒 | API 调用约 17.11 秒 |
| 主要局限 | 受模型类别和检测效果限制 | 可能产生不准确或未经验证的描述 |

需要说明的是，YOLO 的 6.9 毫秒为模型推理耗时，而视觉大模型的 17.11 秒为 API 调用响应耗时，二者的统计范围不同，因此不能直接据此进行严格的速度性能比较。

### 4.4 初步分析

本次实验表明，两种方案具有不同的功能特点。YOLO 更适合需要快速获取目标类别、数量和位置的任务；视觉大模型更适合生成自然语言描述、辅助理解图片中的整体场景。

对于同时需要目标定位和场景语义分析的应用，可以考虑结合两种方案：先使用目标检测模型提取目标信息，再利用视觉大模型进行补充说明。不过，组合方案的实际效果仍需要通过进一步实验验证。

## 五、方案比较与适用场景

### 5.1 功能特点比较

YOLO 目标检测和视觉大模型分析具有不同的功能特点。

YOLO 主要针对图像中的具体目标进行检测，可以输出目标类别、置信度和目标位置等结构化信息，适合需要快速识别和定位目标的应用场景。

视觉大模型则更加侧重图像内容的整体理解，可以根据图片生成自然语言描述，对物体、环境以及场景之间的关系进行综合分析，适合需要语义理解和文字描述的应用场景。

### 5.2 适用场景

YOLO 适用于目标数量统计、目标定位、实时检测等任务，例如交通目标检测、人员检测和工业目标检测等。

视觉大模型适用于图片内容描述、场景理解、图像问答以及辅助信息提取等任务。

如果一个应用同时需要目标定位和复杂的场景理解，可以考虑结合两种技术，使目标检测和语义分析相互补充。

### 5.3 方案局限性

YOLO 的检测能力受到训练数据和模型类别的限制，对于模型未覆盖或较难识别的目标可能无法得到理想结果。

视觉大模型虽然具有较强的场景理解能力，但生成内容可能存在识别错误或推断不准确的情况。同时，本项目通过网络 API 调用视觉大模型，其响应时间受到网络环境和服务端处理时间等因素影响。

因此，在实际应用中应根据具体任务选择合适的视觉分析方案，并对模型输出进行必要的验证。

## 六、总结与不足

### 6.1 项目总结

本项目完成了一个结合目标检测模型和视觉大模型的图片智能分析系统。

通过 YOLO 目标检测功能，系统能够对图片中的目标进行识别和定位，并输出目标类别、置信度以及可视化检测结果。通过视觉大模型 API，系统能够对图片进行自然语言形式的场景分析，从整体环境、主要物体和图片信息等方面进行描述。

通过对同一张测试图片进行实验，可以看出两种视觉分析方案具有不同的特点。YOLO 更适合目标检测和定位任务，视觉大模型更适合复杂场景理解和自然语言描述。两种方案可以根据实际应用需求单独使用，也可以进一步结合。

### 6.2 项目不足

目前项目仍存在一些不足：

1. 实验测试图片数量较少，目前主要使用单张公交车图片进行功能验证，尚不足以全面评价模型性能。
2. YOLO 当前主要使用预训练模型，尚未针对特定应用场景进行专门训练。
3. 视觉大模型通过 API 进行调用，响应时间受到网络环境和服务端状态等因素影响。
4. 视觉大模型的分析结果可能存在一定误差，需要结合原始图片进行人工核验。
5. 当前系统主要以命令行方式运行，用户交互界面仍比较简单。

### 6.3 后续改进方向

后续可以从以下几个方面进行改进：

1. 增加更多不同类型的测试图片，对两种方案进行更加全面的实验。
2. 针对具体应用场景收集数据，并进一步训练或优化目标检测模型。
3. 对视觉大模型的提示词进行优化，提高分析结果的稳定性和针对性。
4. 增加更加直观的图形化交互界面，提高系统的易用性。
5. 进一步结合目标检测和视觉大模型，使系统同时具备目标定位和场景语义理解能力。
